# パフォーマンス方針

## 更新処理の統合

カウントダウン（秒単位）、プログレスバー（秒単位）、太陽・月の位置、パーティクルアニメーションなど、複数のリアルタイム処理が同時に動く。それぞれが個別の`setInterval`/`requestAnimationFrame`を持つと無駄が多いため、**単一の更新ループに統合**する（実装方式の詳細は実装時に検討）。

## タブ非表示時の更新停止

Page Visibility API（`document.visibilityState`）を使い、タブがバックグラウンドにある間はリアルタイム更新・アニメーションを停止する。バッテリー消費・CPU負荷を抑える。

## `prefers-reduced-motion`への対応

- **方針**: OSの「アニメーションを減らす」設定が有効なユーザーには、背景アニメーション・パーティクル演出を大幅に削減し、静止背景に近づける
  - 前庭障害等への配慮として設計された設定のため、速度を緩めるだけでなく、大きな動き自体を止める対応とする
  - カウントダウンの数字切り替わりなど、機能的に意味のある最小限のアニメーションは維持する
- **実装タイミング**: 初期デプロイ後に対応する（MVPでは未対応のまま進める）

## モバイル・低スペック端末でのパーティクル数調整

- **初期実装**: デバイス・画面幅によらず全環境で同一のパーティクル表現とする
- **デプロイ後**: デバイス種類・画面幅に応じてパーティクル数を自動調整し、低スペック端末での発熱・バッテリー消費・FPS低下を回避する

## 画像最適化

- OG画像・シェア画像・背景イラスト等の静的アセットは、`next/image`等を活用し、WebP/AVIF等の最適なフォーマット・サイズで配信する
- AI生成イラストは容量が大きくなりがちなため、保存前に圧縮・最適化する

## Core Web Vitals目標値

一般的な「良好」基準を採用する。

| 指標                             | 目標値  |
| -------------------------------- | ------- |
| LCP（Largest Contentful Paint）  | < 2.5秒 |
| CLS（Cumulative Layout Shift）   | < 0.1   |
| INP（Interaction to Next Paint） | < 200ms |

アニメーションが多い実装のため、特にCLS・INPは実装中も継続的に意識する。
