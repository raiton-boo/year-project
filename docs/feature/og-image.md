# OG画像（動的生成）

## ステータス

検討中

## 概要

季節感のあるイラスト背景の上に、残り日数を大きくプログラムで重ねて描画する動的OG画像。
背景イラストはAIで事前生成した静的アセットを使い、日付に応じて決定的に1枚を選択する。テキスト部分のみリクエスト毎に動的生成する。

## アニメーションについて（検討の結論）

`og:image`に動画・GIF等を指定しても、X・Facebook・LINEなど主要SNSのリンクプレビューはほぼ全て静止画（1枚目のフレーム）としてしか扱わない。そのため**アニメーションは実装しない**（静止画のみ）。

## 画像サイズ

標準的なOGPサイズ **1200×630px** を採用する。

## 背景イラスト

### 用意方法

- 自分で好きなAIツール（Midjourney等）を使い、**事前にシーンごとの画像を生成・厳選して静的アセットとして保存**する
  - リクエスト毎にAI画像生成APIを呼ぶ方式は品質が不安定でコスト・レイテンシも増えるため採用しない
- 保存先は実装時に決定（Cloudflare R2 等を想定）

### イラストのテイスト例

季節感・情緒のある具体的なワンシーンを想定。

- 夏: 夜の花火、田舎の祖父母宅のベランダで切ったスイカ、氷水に浸したソーダ瓶 など
- 冬: 夜の街灯に雪がちらつく風景、雪だるま など
- 他の四半期・特別な日も同様に、季節や行事を感じさせる具体的なワンシーンで構成する

### バリエーション数

- **四半期（Q1〜Q4）ごとに2〜3枚**
- **特別な日ごとに1枚**: ハロウィン(10/31)、クリスマス(12/25)、元日(1/1)、大晦日(12/31)、バレンタインデー(2/14)、七夕(7/7)

合計 約14〜18枚程度を想定。

### 選択ロジック（重要: キャッシュ戦略との整合性）

- OG画像は日付単位でエッジキャッシュする方針（`requirements.md` 3.4参照）のため、**同じ日の中でランダムに背景が変わる実装は不可**
- 対象日が四半期内の通常日の場合、**日付のハッシュ値等から決定的に1枚を選択**する（同じ日に複数回アクセスしても同じ画像になる）
- 対象日が特別な日・年末年始期間に該当する場合は、その専用画像を優先的に選択する

## テキストオーバーレイ

- **残り日数を大きく**中央〜目立つ位置に配置する
- 可読性確保のため、背景イラストの上に半透明の帯・文字の縁取り（ストローク）やドロップシャドウ等を加え、どの背景画像でも視認性を担保する
- プログレスバーやメッセージ文言は、OG画像のサイズでは視認性が低いため**含めない**

## 生成方式（`requirements.md`との関係）

- `requirements.md` 3.4で決定した「リクエスト毎の動的生成 + 日付単位エッジキャッシュ」方針を踏襲
- 実装イメージ: `next/og`（Satori）で背景画像を`<img>`として読み込み、その上に残り日数のテキストをレイヤーとして描画して1枚の画像に合成する
