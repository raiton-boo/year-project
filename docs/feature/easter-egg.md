# 隠し要素・イースターエッグ

## ステータス

検討中

## 概要

複数のトリガー方法を用意し、発見したユーザーに画面全体の特別なアニメーションを見せる隠し機能。発見・拡散自体をSNSでのバズ要素として狙う。

## トリガー一覧

異なるユーザー層（PC/モバイル/エンジニア/探索好き）それぞれに向けて、複数のトリガーを用意する。

1. **コナミコマンド**: `↑↑↓↓←→←→BA`
2. **ロゴ/数字連打**: 特定の要素を規定回数クリック
3. **特定の文字列入力**: 例として「2026」等と打つと発動（ページ上でキー入力を監視）
4. **スマホのシェイク検出**: `devicemotion`イベントで端末を振ると発動
5. **DevToolsコンソールの隠しコマンド**: コンソールにASCIIアート＋ヒントメッセージを表示し、特定の関数実行等で発動
6. **秘密のURLパラメータ**: 例 `?secret=2026` のようなクエリパラメータでアクセスすると発動

### DevToolsコンソール連携の補足

- HTMLソースコード中にもコメントでヒントを仕込んでおく（「ソースを見る」→「コンソールのヒントに気づく」→「発動」という発見の導線を作る）

## 発動時の演出

- 画面全体に特別なアニメーション（花火・雪などのパーティクル演出が極大発生するイメージ）
- 既存のパーティクル演出（`feature/progress-bar.md`・`feature/messages.md`の節目演出）の仕組みを流用し、通常より大規模・派手な形で再利用する想定

## 見送ったトリガー

- カウントダウンの数字を連打するトリガー: 対象となる時間帯にページを開いているとは限らないため、今回は見送り

## 未決事項

- 各トリガーの具体的な実装仕様（文字列入力の検知範囲、連打のクリック対象・回数など）
- 発動時アニメーションの具体的な表現 → ワイヤーフレーム作成時
- 一度発動した後の再発動可否（連打防止・クールダウンの要否）
- アクセシビリティへの配慮（派手な演出のため、アニメーション低減設定時の挙動）
