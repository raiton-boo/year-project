# ワイヤーフレーム方針

## 進め方

**2段階**で進める。

1. **低忠実度**: 構造・配置のみを白黒・グレースケールの簡易な見た目で決める（色・フォント・アニメーションは入れない）
2. **高忠実度**: 低忠実度版に合意した後、実際の色・フォント・アニメーションを入れたプロトタイプで雰囲気を確認する

構造の議論と見た目の好みの議論を分離し、一度に両方を変更しようとして収拾がつかなくなることを避ける。

## 作成形式

- **Claude Artifact（HTML/CSS/JS）** で、実際にブラウザ上で表示・操作できるプロトタイプとして作成する
- Figma等の外部デザインツールは使用しない
- アニメーション・インタラクションが多いサイトのため、静止画の図よりも実際に動くプロトタイプの方が意思決定に向いている

## 対象範囲（今回）

- **トップページの基本レイアウトのみ**に絞る
- 対象機能: カウントダウン、プログレスバー、時期によって変わる文言、背景アニメーション、SNSシェア、タブタイトル/favicon、ダークモード切り替えUI、累計訪問者数（フッター）
- **対象外（後回し）**: 特定の日・アーカイブページ用の個別バリエーション、隠し要素・イースターエッグの演出、OG画像・シェア画像自体のデザイン（これらは別途`feature/og-image.md`等で改めて検討する）

## 基準ビューポート・ブレークポイント

- **ブレークポイント**: Tailwind CSS v4標準（`sm:640px` / `md:768px` / `lg:1024px` / `xl:1280px`）
- **基準として作成するビューポート**: モバイル375px、PC1440px の2パターン
  - タブレット等の中間サイズは専用デザインを作らず、上記2パターンの間をTailwindのブレークポイントで滑らかに補間する（実装はレスポンシブなクラスで自然に繋げる）
  - 実装方針: `lg:`（1024px）でPC版レイアウトに切り替える想定。それ未満（タブレット幅含む）はモバイル版の縦積みレイアウトがそのまま適用される
  - リング(320px)・シェアパネル(900px)等、低忠実度版でpx固定にしている値は、実装時に`max-width`＋`%`ベースの可変サイズにし、タブレット幅で窮屈にならないようにする
  - 高忠実度・実装段階で、タブレット幅表示時に不格好に見えないかを一度目視確認する

## ファーストビュー（スクロールなし）の情報設計

スクロールせずに見える範囲には、以下のみを配置する。

- カウントダウン
- プログレスバー
- 時期によって変わる文言
- 背景アニメーション

以下はスクロール下に配置する。

- SNSシェアボタン
- 累計訪問者数（フッター）
- その他の補足情報

## 低忠実度ワイヤーフレーム v2（決定事項）

- カウントダウンとプログレスバーは、**リング型の一体型ヒーロービジュアル**として統合表示する（リングの中央に残り日数・時刻・進捗%を表示）。`feature/countdown.md`・`feature/progress-bar.md`で定義した横長バー/リング型の切り替えは、この一体型ビジュアルの形状切り替えとして実現する
- **形状切り替え（リング⇄横長）の操作方式**:
  - PC: クリックで切り替える小さなトグルコントロール
  - モバイル: 横方向のスワイプ＋タップ可能なドットインジケーター（スワイプのみに頼らず、発見性・アクセシビリティを確保する）
  - 具体的な見た目・切り替わるアニメーションの質感は高忠実度段階で決定する
- **SNSシェア**: ボタンを直接並べず、「シェアする」という1つの入口から開く**パネル形式**にする
  - パネル内は「📝 テキストでシェア」（アスキーアートのスタイル選択 → プレビュー → SNS投稿ボタン）と「🖼️ 画像でシェア」（縦/横切替 → プレビュー → ダウンロード/共有ボタン）の**2枚のカードに分割**する
  - PCは2カードを横並び、モバイルは縦積みで配置する
- **モバイルヘッダー**: ロゴアイコン＋サイト名（左）、ダークモードのアイコンボタン（右）を独立したヘッダーバーとして配置する

## 高忠実度ワイヤーフレーム v2（決定事項）

季節サンプルとして「田舎の夜・蛍」のテーマで作成し、デザインの方向性を確認した（v1の「夏の夜・花火」テーマから、配色・フォント・アイコンを全面的に見直し）。

### タイポグラフィ

- **数字（カウントダウン・残り日数）**: `Fredoka`（丸みを残しつつモダンで洗練された印象）
- **日本語テキスト（メッセージ・ラベル等）**: `M PLUS Rounded 1c`（丸ゴシックだが`Zen Maru Gothic`よりクセが少なく、現代的なアプリに近い雰囲気）
- いずれもGoogle Fonts。`tech-stack.md`にも記録する

### アイコン

- **Phosphor Icons**で統一する（絵文字は使用しない）
- SNSのブランドロゴ（X/LINE/Facebook/はてな/Threads）は、文字マーク（円の中にテキスト）で代替表現している。本番実装では別途ブランドロゴ用のアイコンセット（Simple Icons等）の採用を検討する
- ワイヤーフレーム作成ツールの制約上、実際のPhosphor Iconsライブラリは読み込めないため、同じ見た目（線画・丸みのあるストローク）のSVGを手描きで再現している。本番実装では実際に`@phosphor-icons/react`等のパッケージを導入する

### 配色・ビジュアルスタイル（v3で再調整）

v2では蛍の黄緑色をボタン・アイコン・枠線など画面全体に多用した結果、「夜らしさより蛍色が画面を支配している」という問題が発生したため、以下のように再調整した。

- **背景（夜色を主役に）**: 青黒寄りの夜空グラデーション`#060b16 → #0a1a2e → #0d2230 → #0a1018`に変更（緑・ティール寄りだったv2よりも、はっきり「夜」と分かる配色に）。山や木立のシルエット、遠くの家の灯り、蛍の光の点を配置するのは維持
- **2種類のアクセントカラーに整理し、役割を分離**:
  - **蛍グロー`#cfe36b`**: 背景の蛍の光の点、プログレスリングの差し色、メッセージバッジのアイコンなど「装飾・雰囲気づけ」の用途**のみ**に限定
  - **ランタン琥珀色`#e3975a`**: ボタン・トグルの選択状態・アイコンの強調色など「インタラクティブなUI」の用途に限定（蛍色を全面展開しない）
  - この2色を分離したことで、UIチェックは夜色主体に、蛍色は本当に「点」として効くようになった
- **UI要素（カード・バッジ・トグル等）**: 半透明の白＋ぼかし（グラスモーフィズム）`background: rgba(255,255,255,0.05〜0.12)` + `backdrop-filter: blur()` で、背景アニメーションの上に浮いているような質感にする（この手法自体は維持）
- **ボタン・コントロールの方向性統一**: プライマリ操作（フル表示トグルの選択中、共有する、等）は常にランタン色のグラデーション塗り＋クリーム文字、セカンダリ操作（ダウンロード等）は常にグラスの枠線のみ、という2種類のスタイルに統一
- 季節が変わると、背景のシーン・装飾（蛍→桜吹雪→落ち葉→雪など）が切り替わる想定（`feature/background-animation.md`参照）。その際のアクセントカラーの組み合わせ（蛍色＋ランタン色、のような2色構成）は季節ごとに検討する

### リング型ヒーローの表現

- 外側のリングをランタン色→蛍色のグラデーションで進捗分だけ塗り、残りは半透明の白トラックにする（`conic-gradient`で表現）
- 内側はガラス質感の円（暗めの半透明＋ぼかし）に、数字・時刻・進捗%を配置する
- **塗り足しアニメーション**: 初回表示時に0%から現在の進捗率まで、約1.4秒・イージング（ease-out cubic）で滑らかに塗り足される。実装は`conic-gradient`の進捗角度をコンポーネントの状態として持ち、`requestAnimationFrame`で毎フレーム更新する方式で検証済み（外部アニメーションライブラリ不要）

### シェアカードの高さ調整

- PCの「テキストでシェア」「画像でシェア」の2カードは、グリッドを`align-items: stretch`にし、カード内部を`flex`＋`margin-top: auto`でボタン類を下端に揃えることで、コンテンツ量が違っても2カードの高さが揃うようにした

### 累計訪問者数カウンター

- 単なるテキスト表示から、アイコン（人物アイコン）＋テキストをグラスのピル型バッジに収めた表現に変更

### プログレスバー（横長）版ヒーロー

- リング型と並ぶもう一方の表示モードとして、横長バー版のヒーローを作成（`BarHero-PC.dc.html` / `BarHero-Mobile.dc.html`）
- カウントダウンの数字を上部に大きく表示し、下に横長バー＋現在位置のピン（整数%表示）を配置する構成
- 形状切替インジケーター（ドット）は、リング版と見た目を共有しつつ選択中の状態が入れ替わるようにした

### 季節バリエーションについて

- **UIのアクセントカラーは季節を問わず共通**にし、ブランドとしての一貫性を保つ方針を確認（変化するのは背景の装飾色・シーンのみ）
- 春の試作アートボードは、デザイン方向性確定（方向性F採用）に伴い整理済み。秋・冬・年末年始等のバリエーションは実装時に必要に応じて作成する

### 時間帯バリエーション（明け方・朝・昼・夕方・夜・真夜中）

夏をベースに、1日の時間帯による背景の変化を6段階で検証した（`TimeDawn-PC.dc.html`〜`TimeMidnight-PC.dc.html`）。

- 空の色・太陽/月の位置・彩度を時間帯ごとに変化させた
  - 明け方: 紺〜紫〜暖色の地平線、太陽が低い位置に薄く覗く
  - 朝・昼: 明るい青空、太陽の位置が高くなる（昼が最も高い）
  - 夕方: 紫〜オレンジの夕焼け、太陽が反対側の低い位置に
  - 夜・真夜中: 既存の夜配色をベースに、月の位置・星の数・蛍の見え方を変化（真夜中は蛍が少なく星が多い、月が高い位置）
- **文字・UIパネルのコントラスト対策**: 朝・昼など明るい空でも文字が読めるよう、グラスパネルの背景を`rgba(255,255,255,0.05)`系の明るいガラスから、`rgba(8,14,22,0.35)`という暗めの半透明に統一した（空が明るくても常にクリーム色の文字が読める）
- カウントダウンの残り日数・メッセージ文言はあえて全時間帯で固定し、「時間帯による見た目の変化」だけを比較できるようにした

## デザイン方向性の決定

配色・フォントの方向性について複数案（A〜G）を比較検討した結果、**方向性F「イラストポップ融合」**を正式に採用した。`MainHiFi.dc.html` / `MobileHiFi.dc.html`（トップページ全体のモックアップ）・`RingAnimationTest.dc.html`はすべてこの方向性で更新済み。

- **フォント**: 数字`Fredoka` / 日本語`Zen Maru Gothic`
- **配色**: 紺〜ティール〜金色のグラデーション（彩度を上げた、温かみのあるイラスト調の夜景）。UIのアクセントカラーは金色系（`#f2c14e`）＋暖色オレンジ（`#e8894a`）のグラデーションに統一
- 季節・時間帯のイラスト演出（蛍・桜・紅葉・雪等）とも自然に馴染む、情緒と彩度のバランスを取った方向性として選定
- 比較検討の過程で作成した他案（A〜E、G）・単体ヒーロー等の試作アートボードは、方向性確定に伴いキャンバスから整理済み

## ワイヤーフレーム作業の区切り

ドキュメント整備・ワイヤーフレーム（低忠実度→高忠実度→デザイン方向性確定）はここで一区切りとする。**以降の実装（Next.jsプロジェクトのコーディング）はユーザー自身が進める。** 細かいビジュアル調整（配色の微調整、具体的なスペーシング等）は、実装時に都度judgeする方針とする。

キャンバスに残したアートボードは、実装時の参考資料として以下の用途で使う。

- `Main.dc.html` / `Mobile.dc.html`: 構造・配置の参考（低忠実度）
- `MainHiFi.dc.html` / `MobileHiFi.dc.html`: 配色・フォント・コンポーネントデザインの参考（方向性F確定版）
- `RingAnimationTest.dc.html`: リング塗り足しアニメーションの実装方式（`requestAnimationFrame`+イージング）の参考
- `BarHero-PC.dc.html` / `BarHero-Mobile.dc.html`: 横長プログレスバー表示モードのレイアウト参考
- `TimeDawn-PC.dc.html`〜`TimeMidnight-PC.dc.html`: 背景アニメーション（`feature/background-animation.md`）の時間帯ごとの配色・太陽/月の位置の参考

- 季節バリエーション×時間帯バリエーションを他の季節にも展開するか（今回は夏のみで方向性確認）

- 蛍のアニメーション演出の詳細（本番はLottieで実装、`feature/background-animation.md`参照）
- 太陽・月の実際の軌道計算（`suncalc`）と、今回作成した6時間帯のビジュアルをどう対応付けるか（実装時の調整）
