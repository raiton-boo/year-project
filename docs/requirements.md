# 要件定義書

## 1. 概要

今年の残り時間を視覚的に伝えるWebサイト。
カレンダー年（1/1 〜 12/31 23:59:59）を対象に、残り時間・進捗率・時期に応じたメッセージを表示する。

## 2. 目的・ターゲット

- 個人の趣味開発・技術アピール（5割）
- 不特定多数への公開・バズ化（5割）

上記の両立を目指す。技術的な作り込み（アニメーション、動的OG画像など）と、SNSでシェアされた際の見栄え・拡散性の両方を重視する。

## 3. 機能要件

### 3.1 残り時間表示

- **対象期間**: その年の 12/31 23:59:59 まで
- **表示粒度**: 3段階で自動切り替え（具体的な閾値日数はワイヤーフレーム作成時に確定）
  1. 日のみ表示（残り日数が多い期間）
  2. 日＋時間まで表示（残り日数が少なくなった期間）
  3. 日＋時間＋分＋秒まで表示（直前期間）
  - ユーザーが表示単位を任意で切り替えられるUIも用意する（自動段階とは別に手動オーバーライド可能）
- 年をまたいだ瞬間（1/1 00:00:00）の挙動（翌年のカウントへの自動切り替え、新年メッセージの表示など）は別途ワイヤーフレーム段階で設計する

### 3.2 プログレスバー

- その年（1/1 〜 12/31）の経過率を示す単一のプログレスバー
- 経過率に応じてイージング・アニメーションで滑らかに表示（motionで実装）

### 3.3 時期によって変わる文言

以下のタイミングで表示文言を切り替える。

- 四半期・季節ごと（春夏秋冬 / Q1〜Q4など）
- 残り日数の節目ごと（例: 残り100日、残り1ヶ月、残り1週間など）
- 年末年始の特別な期間（**12/25 〜 翌年1/3** 程度）のみ、専用の文言・演出にする

具体的な文言内容・節目の日数はワイヤーフレーム作成時に確定する。

### 3.4 OG画像（動的生成）

- **変化させる要素**:
  - 背景デザイン・色テーマ（季節感を反映）
  - 残り日数・進捗率を画像内に動的描画
- **生成方式**: リクエスト毎の動的生成 + 日付単位でのエッジキャッシュ
  - キャッシュキーを日付（YYYY-MM-DD）単位にし、`Cache-Control: public, max-age=86400` 等でCloudflareのエッジにキャッシュ
  - 1日の最初のアクセス時のみ実際に画像生成、以降はキャッシュ返却でコストを抑制
  - バズによるアクセス急増時もコストが線形に増えない設計とする

### 3.5 SNSシェア機能

- 対応プラットフォーム: X (Twitter)、LINE、Facebook、はてなブックマーク、Threads、リンクコピー（モバイルはWeb Share APIも利用）
- シェア時のテキストには現在の残り日数を自動挿入する
- シェア画像は3.4のOG画像をそのまま利用する

### 3.6 ページ構成

- **現時点で確定**: トップページ（LP型単一ページ）のみ
- **将来検討**: 過去の年の記録ページ（その年のサイトの静的アーカイブ、全ユーザー共通・パーソナライズなし）
  - About等その他ページは未定、今後必要に応じて追加

## 4. 非機能要件

### 4.1 パフォーマンス

- Core Web Vitals（LCP, CLS, INP等）を意識した実装
- 詳細な数値目標は実装着手時に検討

### 4.2 SEO

- 動的title/description（残り日数を反映した内容に日次で更新）
- 構造化データ（JSON-LD）対応
- sitemap.xml / robots.txt（ページ数は少ないが基本整備として用意）

### 4.3 アクセシビリティ

- 詳細要件は今後検討（最低限のコントラスト比・セマンティックHTMLは意識する）

### 4.4 アナリティクス

- Cloudflare Web Analytics を導入（Cookie不要、プライバシー配慮）

## 5. 対応言語・デバイス

- 言語: 日本語のみ（多言語対応は将来検討）
- デバイス: レスポンシブ対応（PC / スマートフォン両対応）

## 6. アニメーション要件（motion使用）

- 数字の切り替わり演出（秒カウント等）
- プログレスバーのイージング・アニメーション
- ページ全体の背景演出（パーティクル / グラデーションなど）
- 節目到達時の特別演出（パーティクル爆発など）

## 7. デザイン方向性

- 現時点では「ポップ・グラデーション・季節感」寄りの方向性を想定
- 詳細はワイヤーフレーム作成時に確定する

- デザインの最終的な方向性（配色・フォント等。ワイヤーフレーム作成時に確定）
- 過去の年の記録ページの実装要否・タイミング
- About等トップページ以外の追加ページ
- 追加機能全般
- Git運用（ブランチ戦略・コミット規約・Issue/PR運用）
