# タイムゾーンの基準

## 決定

**サイト全体でJST（Asia/Tokyo, UTC+9）固定**とする。ユーザーのローカルタイムゾーンは使用しない。

## 対象範囲

以下すべてをJST基準で統一する。

- カウントダウン・プログレスバーの「年の終わり（12/31 23:59:59 JST）」判定
- 表示単位の自動切り替え閾値（`feature/countdown.md`）
- 季節・四半期の切り替わり（`feature/messages.md`）
- 節目メッセージ・年末年始期間・特別な日の判定（`feature/messages.md`, `feature/og-image.md`）
- OG画像・シェア画像のキャッシュキー（日付単位）
- 過去の年のアーカイブスナップショット生成のCron Trigger実行（`feature/archive.md`）
- ダークモードの「時間によって同期」の時刻判定（`feature/dark-mode.md`）

## 決定理由

- 対象言語が日本語のみ（`requirements.md` 5章）であり、海外ユーザー向けのローカライズを想定していないため、ユーザーごとのタイムゾーン分岐は不要
- OG画像・アーカイブ生成・特別な日の判定は、クローラーやCronがサーバーサイドで実行するため、もともとJST基準が必須だった
- **サイト本体もJST固定にすることで、「シェアされたOG画像の残り日数」と「実際にページを開いた時の表示」が食い違う不整合を防げる**（ユーザーごとのタイムゾーンだとこのズレが発生しうる）
- タイムゾーン検出・フォールバック処理が不要になり、実装がシンプルになる

## 背景アニメーション（天候・位置情報）との関係

`feature/background-animation.md`の天候・太陽/月の位置計算は、本ドキュメントの「年の判定基準」とは別の話であり、引き続きユーザーの位置情報（Cloudflare `request.cf`のタイムゾーン・緯度経度）を使用する。**「今が何年何月何日か」の判定はJST固定、「その場所が今何時で太陽がどこにあるか」はユーザーの位置基準**、という2つの異なる軸であることに注意する。
